1 · Dictionaries

A dictionary (dict) stores key → value pairs inside { }. You look values up by key, not by position. It's Python's version of a JavaScript object used as a map (docs).

module = {"name": "LLM fundamentals", "hours": 45}
module["name"]           # 'LLM fundamentals'
module["hours"] = 50     # change a value
module["done"] = False   # add a new key
del module["done"]       # remove a key
len(module)              # 2 pairs
JS habit to drop: no dot access In JS you'd write module.name. In Python that's an error for a dict. Always use module["name"], with quotes. (Dot access is for objects made from classes, in Topic 11.)

Missing keys: [ ] vs .get()

CodeIf the key is missing
progress["Capstone"]KeyError: 'Capstone' (JS would give undefined)
progress.get("Capstone")None
progress.get("Capstone", "not started")'not started', the default you chose
"Capstone" in progressFalse. in checks keys only, never values

Use [ ] when the key must be there (a crash tells you about a bug). Use .get() when missing is normal.

Looping over a dictionary

.items() gives you each key and value together (docs). Dicts remember the order you added keys in.

levels = {"python": 2, "rag": 1}
for skill, level in levels.items():
    print(f"{skill}: {level}/5")
# python: 2/5
# rag: 1/5

A plain for key in levels: loops over the keys only. The skill, level part is tuple unpacking, explained next.

Keys must be unchangeable

Strings, numbers and tuples can be keys. Lists can't, because they can change: {["a"]: 1} gives TypeError: cannot use 'list' as a dict key (unhashable type: 'list'). Values can be anything, including lists and other dicts.

2 · Tuples

A tuple is like a list inside ( ), but immutable: once made, it can't change (docs). Use it for a small, fixed bundle of values that belong together, like a (name, hours) pair.

longest = ("LLM fundamentals", 45)
longest[0]           # 'LLM fundamentals': indexing works like lists
longest[1] = 50      # TypeError: 'tuple' object does not support item assignment
longest = ("Capstone", 50)   # fine: this makes a NEW tuple, it doesn't change the old one

Unpacking

You can pull a tuple apart into variables in one line. It's like JS array destructuring const [name, hours] = longest, without the brackets:

name, hours = longest        # name = 'Capstone', hours = 50
a, b = b, a                  # swap two variables
The comma makes the tuple ("ai") is just the string 'ai' in brackets. A one-item tuple needs a trailing comma: ("ai",). The empty tuple is ().

3 · Sets

A set is an unordered collection with no duplicates (docs). It's like JS new Set(), with built-in maths operators:

have = {"python", "rag", "python"}   # → {'python', 'rag'}: the duplicate is dropped
need = {"python", "evals", "pytorch"}
have.add("sql")      # sets are mutable; .add() instead of .append()
have & need          # {'python'}             in BOTH (intersection)
need - have          # {'evals', 'pytorch'}   in need but NOT in have (difference)
have | need          # everything from either (union)
  • Sets have no order and no indexes: have[0] is an error. The printed order can differ from run to run. Use sorted(have) to get a sorted list when you need a stable order.
  • set(words) turns a list into a set, dropping duplicates.
Trap: {} is an empty dict {} makes an empty dictionary, not an empty set. For an empty set, write set().

Which one should I use?

TypeLooks likeUse it for
list[1, 2]an ordered collection that grows or changes
dict{"k": 1}looking things up by name; a record with named fields
tuple(1, 2)a small fixed bundle; returning several values (Topic 6)
set{1, 2}unique items; "what's in A but not B?"

Why this matters for AI work: API responses from LLMs arrive as JSON, which becomes dicts and lists in Python. A chat is a list of dicts like {"role": "user", "content": "..."}. You'll see this shape in every Module 3 lesson.

    05_study_plan_v5.py

    # Study plan v5: dictionaries, tuples and sets.
name = input("Your name: ").strip().title()
if not name:
    name = "Friend"
target_role = input("Target role: ").strip()

while True:
    hours_per_week = float(input("Hours per week (1-80): "))
    if 1 <= hours_per_week <= 80:
        break
    print("Please enter a number from 1 to 80.")

# A set: duplicates are dropped automatically.
my_skills = set()
while True:
    skill = input("Add a skill (blank to finish): ").strip().lower()
    if not skill:
        break
    my_skills.add(skill)

# A list of dictionaries: each module keeps its name and hours together.
modules = [
    {"name": "Python basics", "hours": 40},
    {"name": "Python for web and APIs", "hours": 25},
    {"name": "LLM fundamentals", "hours": 45},
    {"name": "LangChain and LangGraph", "hours": 25},
    {"name": "Classic ML", "hours": 30},
    {"name": "Neural networks", "hours": 35},
    {"name": "Fine-tuning", "hours": 25},
    {"name": "Capstone", "hours": 45},
]
progress = {"Python basics": "in progress"}  # module name -> status

total_hours = 0
longest = ("", 0)  # a tuple: (name, hours) of the best so far
for module in modules:
    total_hours += module["hours"]
    if module["hours"] > longest[1]:
        longest = (module["name"], module["hours"])
weeks = total_hours / hours_per_week

print("=" * 40)
print(f"Study plan for {name} as {target_role}")
print(f"{len(modules)} modules, {total_hours} hours, {weeks:.1f} weeks")
print("-" * 40)

for i in range(len(modules)):
    module = modules[i]
    status = progress.get(module["name"], "not started")
    print(f"{i + 1}. {module['name']} ({module['hours']} h): {status}")

longest_name, longest_hours = longest  # unpack the tuple
print(f"Longest module: {longest_name} ({longest_hours} h)")

words = target_role.lower().replace("-", " ").replace("/", " ").split()
ai_keywords = {"ai", "ml", "llm"}
if ai_keywords & set(words):  # a non-empty set is truthy
    ai_skills = {"python", "llm apis", "rag", "evals", "pytorch"}
    print("-" * 40)
    print("AI role: Modules 3 and 4 will matter most.")
    print(f"Skills you have: {', '.join(sorted(ai_skills & my_skills))}")
    print(f"Skills to learn: {', '.join(sorted(ai_skills - my_skills))}")
print("=" * 40)

    Inside the f-strings, module['name'] uses single quotes so they don't clash with the outer double quotes. (Python 3.12+ allows matching quotes too, but mixing them is easier to read.) And look at the AI check: the whole Topic 4 keyword loop became one line, ai_keywords & set(words).

Practice: recall, don't reread

1. What does this print?

levels = {"python": 3, "rag": 1}
print(levels["rag"])
Look up by key: "rag" maps to 1.

2. What does this print?

levels = {"python": 3, "rag": 1}
print(levels.get("evals", 0))
"evals" isn't a key, so .get() returns the default, 0.

3. What does this print?

levels = {"python": 3, "rag": 1}
print(3 in levels)
in on a dict checks keys. 3 is a value, not a key.

4. What does this print?

print(len({"rag", "evals", "rag"}))
It's a set, so the second "rag" is dropped. Two items are left.

5. What does this print?

name, hours = ("Capstone", 45)
print(hours)
Unpacking puts the first item in name and the second in hours.

6. What does this print?

print(type({}))
{} is an empty dict. An empty set is set().

7. What does this print?

have = {"python", "rag"}
need = {"rag", "evals"}
print(have & need)
& keeps items that are in both sets.

8. Which of these can't be a dictionary key?

Keys must be unchangeable. A list can change, so it can't be a key. A tuple can't change, so it can.

Answer from memory

When would you use d["key"], and when d.get("key", default)?

[ ] when the key must exist, because a missing key is a bug and the KeyError tells you. .get() when a missing key is normal and a default makes sense.

What's the difference between a list and a tuple?

A list is mutable (append, change items). A tuple is immutable: you can only make a new one. Tuples suit small fixed bundles like (name, hours).

How do you find the skills you still need to learn, given two sets?

need - have: the items in need that aren't in have.
