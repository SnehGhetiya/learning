1 · Lists

A list holds many values in order, inside [ ], separated by commas. It's Python's version of a JavaScript array.

skills = ["python", "rag", "evals"]
module_hours = [40, 25, 45]
empty = []

Getting items out: indexing and slicing

Every item has a position, called its index, starting at 0.

CodeResultMeaning
skills[0]'python'first item
skills[-1]'evals'last item (negative indexes count from the end, like JS arr.at(-1))
skills[0:2]['python', 'rag']a slice: from index 0 up to, but not including, 2
len(skills)3number of items
skills[5]IndexError: list index out of rangeno item there (JS would quietly give undefined)

Indexing and slicing also work on strings: "python"[0] is 'p', and "python"[0:3] is 'pyt'.

Changing a list

Unlike strings, lists are mutable: you can change them in place (list methods).

skills.append("pytorch")   # add to the end → ['python', 'rag', 'evals', 'pytorch']
skills.remove("rag")       # remove the first match → ['python', 'evals', 'pytorch']
skills[0] = "Python"       # replace by index
"rag" in skills            # False: `in` works on lists too
Mutable vs immutable: the sort trap String methods return a new string. Many list methods instead change the list in place and return nothing. Python's "nothing" is the value None: 
x = [3, 1, 2]
y = x.sort()     # sorts x in place → x is [1, 2, 3]
print(y)         # None, so don't assign the result of .sort()
z = sorted(x)    # sorted() RETURNS a new sorted list, leaving x alone

Strings ↔ lists: split and join

This is the fix for your AI-role check (split, join):

>>> "head of ai".split()           # split on whitespace
['head', 'of', 'ai']
>>> "ai" in "head of ai".split()   # whole-WORD check!
True
>>> "python,rag".split(",")        # split on a separator you choose
['python', 'rag']
>>> ", ".join(["python", "rag"])   # the reverse: glue a list into one string
'python, rag'

"ai" in words on a list checks for a whole item, while "ai" in text on a string checks for letters anywhere. That difference is why "Maintenance" and "Airline" stop matching, and "Head of AI" starts matching.

2 · for loops

A for loop runs a block once for each item (docs). Each time round, the loop variable points to the next item. It's like for (const skill of skills) in JS.

for skill in ["python", "rag", "evals"]:
    print(skill.upper())
# PYTHON
# RAG
# EVALS

The accumulator pattern

This is a very common pattern: start a total before the loop, then add to it inside the loop. total += n is short for total = total + n.

total = 0
for n in [3, 4, 5]:
    total += n
print(total)   # 12. Note: this line is NOT indented, so it runs once, after the loop

Python has a built-in sum() that does this in one call. You'll meet it in Topic 7. Writing the loop yourself first shows you what it does.

range(): looping over numbers

range(3) produces 0, 1, 2: it starts at 0 and stops before the number you give it, just like slices. range(1, 4) produces 1, 2, 3 (docs). Combined with len(), it lets you loop over positions, which is useful when two lists line up:

modules = ["Python basics", "LLM fundamentals"]
module_hours = [40, 45]
for i in range(len(modules)):
    print(f"{i + 1}. {modules[i]} ({module_hours[i]} h)")
# 1. Python basics (40 h)
# 2. LLM fundamentals (45 h)

In Topic 7, enumerate() and zip() make this neater. Learning it with range first makes those easy to understand.

3 · while loops and break

A while loop repeats as long as a condition is true. Use for when you have items to go through, and while when you don't know how many repeats you'll need, such as "keep asking until the answer is valid":

while True:                              # loop forever...
    hours = float(input("Hours (1-80): "))
    if 1 <= hours <= 80:
        break                            # ...until break exits the loop
    print("Please enter a number from 1 to 80.")

break exits the loop immediately (docs). If you forget it, the loop never ends. Press Ctrl+C to stop a stuck program.

8. When should you choose while over for?

for goes through things you already have (a list, a range). while keeps going until a condition changes, like "until the input is valid".

Answer from memory

What's the difference between "ai" in text and "ai" in text.split()?

On a string, in finds the letters anywhere ("maintenance"). On a list of words, it only matches a whole item.

Why is y = x.sort() a bug?

.sort() sorts x in place and returns None. Either call x.sort() on its own line, or use y = sorted(x).

What are the indexes of the first and last items of a 5-item list?

0 and 4. The last one is also -1.
