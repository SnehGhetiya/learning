# Teach each topic first, then a project, then move on

The learner has **no Python experience at all**, and a project-first lesson (a uv project plus a working program on day one) was too much at once. They asked for this structure: learn each Python topic one at a time, then build a project that uses those topics, then move to the next area (for example LangChain) and repeat. The course is now organised as **modules**, each made of **topic lessons followed by one module project**.

**Evidence**: The learner pushed back after Lesson 1 (the uv + `job-radar` project) on 2026-09-23: "I do not have any prior experience to Python… can we first learn python's each topics, then create project then move to the next one".

**Implications**:
- LR-0001's claim that basics can be skipped is corrected. Web development experience helps with analogies (Node, JSON, HTTP), but every Python concept is taught explicitly.
- One new tool or idea at a time. Plain `python3` scripts come first, and uv is introduced in the modules & packages topic, when third-party packages are first needed.
- The project-first lesson is kept in `drafts/phase1-project-job-radar-draft.html` for reuse in the Module 1 project.
