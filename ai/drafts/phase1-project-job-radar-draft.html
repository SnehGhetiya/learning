Why start here

Every AI engineering project you'll build (RAG apps, evals, fine-tuning scripts) is a Python project, with dependencies and a lockfile, not a loose .py file. So we start the way real projects start. You already know this workflow from npm; only the names change.

uv is written in Rust by Astral and replaces pip, venv and pyenv with a single tool. uv docs

Build it

  1. Install uv with the official installer (or brew install uv, since you have Homebrew). Open a new terminal afterwards so your shell can find it. 
    $ curl -LsSf https://astral.sh/uv/install.sh | sh
$ uv --version
  2. Create the project. We'll keep all course projects in one folder. 
    $ mkdir -p ~/Music/learning/ai/projects
$ cd ~/Music/learning/ai/projects
$ uv init job-radar
$ cd job-radar
    You now have pyproject.toml, .python-version (pins Python 3.14), README.md and src/job_radar/__init__.py.
  3. Run it. The first run creates .venv/ and uv.lock automatically, just as the first npm install creates node_modules. 
    $ uv run job-radar
Hello from job-radar!
    job-radar works as a command because pyproject.toml maps it to a function: job-radar = "job_radar:main", meaning "call main in the job_radar package". It's like a "bin" entry in package.json.
  4. Write the real program. Replace everything in src/job_radar/__init__.py with:

    src/job_radar/__init__.py

    # Made-up sample postings. In Lesson 2 we'll load real ones from a file.
postings = [
    {"title": "AI Engineer", "skills": ["python", "rag", "evals"]},
    {"title": "ML Engineer", "skills": ["python", "pytorch", "fine-tuning"]},
    {"title": "LLM App Developer", "skills": ["python", "rag", "typescript"]},
]


def count_skills(postings):
    counts = {}
    for posting in postings:
        for skill in posting["skills"]:
            counts[skill] = counts.get(skill, 0) + 1
    return counts


def main() -> None:
    counts = count_skills(postings)
    print(f"Scanned {len(postings)} postings\n")
    for skill, n in counts.items():
        print(f"{skill:<12} {'#' * n}")
  5. Run it again. You don't need a rebuild: uv installs your own package in editable mode, so your edits are picked up. 
    $ uv run job-radar
Scanned 3 postings

python       ###
rag          ##
evals        #
pytorch      #
fine-tuning  #
typescript   #

Reading the code as a JS developer

Everything in that file maps onto something you already know. Here are the differences that matter:

The official tutorial explains indentation as grouping in §3.2.

Indentation is the syntax. Python has no { } blocks. A line ending in : opens a block, and the block is everything indented under it (use 4 spaces). When the indentation goes back out, the block ends. Semicolons aren't used.

No const/let. counts = {} creates the variable. Lists [...] are arrays, and dicts {"key": value} are like objects, but dict keys are accessed with brackets, posting["skills"], never with a dot.

dict.get(key, default): the reference docs.

Missing keys throw. In JS, obj.missing is undefined. In Python, counts["rag"] raises a KeyError if "rag" isn't there. That's why we write counts.get(skill, 0): it returns the default (0) when the key is absent.

for x in list works like JS for (const x of list) (docs). counts.items() gives (key, value) pairs, like Object.entries(), and for skill, n in ... destructures each pair.

Format specs such as :<12 are covered in the format mini-language docs. Skim it; don't memorise it.

f-strings are template literals. f"Scanned {len(postings)} postings" is `Scanned ${postings.length} postings` (docs). {skill:<12} left-aligns the value in 12 characters. '#' * n repeats a string, like '#'.repeat(n).

len(x), not x.length. Length is a built-in function that works on lists, dicts and strings.

-> None is a type hint, like TypeScript's : void. Python doesn't enforce it when the code runs; tools and editors use it. We'll use type hints much more in later lessons.

Practice: recall, don't reread

Answer from memory. It's supposed to feel a little hard: pulling an answer out of memory is what makes it stick. Reading it again only feels productive.

1. Your npm reflex is npm install zod. Which command adds the httpx package to a uv project?

uv add records the dependency in pyproject.toml, updates uv.lock and installs it into .venv, all in one step (docs).

2. Which folder plays the role of node_modules in a uv project?

.venv is the project's virtual environment: its own isolated Python with its own installed packages. uv creates it on the first uv run. Like node_modules, it stays out of git.

3. In Python, what tells the interpreter that a function's body has ended?

Blocks are defined by indentation alone. Blank lines are only for readability; the convention of two blank lines between top-level functions comes from PEP 8, Python's style guide.

4. What does this print?

counts = {"python": 3}
print(counts.get("rag", 0))
"rag" isn't a key, so .get returns the default, 0. Writing counts["rag"] would crash with KeyError: 'rag'.

5. What does this print? (Python prints dicts with single quotes.)

counts = {"python": 1}
counts["python"] = counts.get("python", 0) + 1
print(counts)
This is the exact counting pattern from count_skills. The key exists, so .get returns 1, then + 1 stores 2. The output is {'python': 2}.

6. What does this print?

skills = ["rag", "evals"]
print(f"{len(skills)} skills")
len(skills) is 2, and the f-string puts it in place: 2 skills.
