# Mission: Become a hireable AI Engineer

## Why
Move from web development into an **AI engineer** role. That means going from never having written Python to building, evaluating and shipping LLM-powered applications. The target is a resume-ready capstone project and enough depth (classic ML, neural networks, fine-tuning) to handle AI engineering interviews with confidence.

## Success looks like
- Writes idiomatic, modern Python (current release, `uv`, type hints), learned from zero, topic by topic.
- Builds LLM apps: calls models via API and locally, gets structured outputs, uses tools, builds RAG, and writes evals to prove quality.
- Trains a classic ML model with scikit-learn and explains train/test splits and metrics.
- Builds and trains a small neural network (up to a tiny GPT) in PyTorch and can explain how it learns.
- Fine-tunes a small open model with LoRA on a free cloud GPU and publishes it to the Hugging Face Hub.
- Ships one deployed, full-stack capstone project (using existing web dev skills) with a README, demo and eval results that can go on a resume.

## Constraints
- **About 10 hours/week** (updated 2026-09-24, was under 5). Topic lessons of 30–40 min, 1–2 per session, each with a tangible win.
- **Free only.** Local models (Ollama; 30 GB RAM, no NVIDIA GPU), free API tiers, free Colab/Kaggle GPUs.
- **Current versions only.** Verify every tool and API against official docs at lesson time. Never teach outdated patterns.
- **Topics first, then projects.** Learn each topic one by one, then build a module project that uses them, then move to the next area. The projects build toward the capstone.
- Complete beginner in Python/AI; experienced in web development.

## Out of scope (for now)
- Heavy math-first theory (math is introduced only when a project needs it).
- Research-level work (novel architectures, paper reproduction beyond a tiny GPT).
- MLOps at scale (Kubernetes, distributed training).
